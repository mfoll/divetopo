# Topo Réunion

Website for sharing a non-exhaustive selection of topo-bathymetric maps of dive
sites in Réunion.
A single viewer brings together 2D maps, 3D perspectives, and interactive
terrain. It opens on the 3D perspective with orthophoto; selecting a basemap
does not duplicate either the displayed map or the interactive geometry.

The website remains in the map repository so that new sites, credits, and Web
renders derive from the same configurations. On large screens, a vertical map
of the west coast acts directly as the site selector; below 900 px, a native
drop-down menu replaces it. Both interfaces and the downloads are driven by
the same generated manifest.

The interface is available in French and English. When no preference is saved,
the language follows the browser setting. The theme offers Light, Dark, and
Auto; Auto is the initial setting and follows the system mode. The same
preference cookies are used across `divetopo.com` and
`reunion.divetopo.com`.

## Routes and search indexing

The neutral root `/` redirects to `/fr` or `/en` from the saved language
preference, then the browser's weighted `Accept-Language` header. The
language-specific overview routes are:

- `/fr`
- `/en`

Every site in `public/maps/manifest.json` also has two indexable routes:

- `/fr/sites/<slug>`
- `/en/sites/<slug>`

These routes server-render the same manifest-driven interface and assets while
opening the selected site directly. Selecting another site updates the URL
without reloading the viewer; browser back and forward navigation restore the
corresponding language and site. The neutral `/sites/<slug>` route redirects
to the visitor's preferred language and serves as the `x-default` alternate.

Each overview and site page publishes a self-referencing canonical URL,
reciprocal French/English `hreflang` links, an `x-default` alternate, localized
Open Graph metadata, and structured data. The crawl entry points are:

- `/robots.txt`
- `/sitemap.xml`

The sitemap is generated from the same map manifest, so a newly published site
is included automatically after its assets are rebuilt.

## Development

Requirement: Node.js `>=22.13.0`.

```bash
npm install
npm run dev
npm test
```

## Cartographic assets

Responsive images and downloadable printable sheets are generated from the
repository's canonical outputs:

```bash
../.venv/bin/python scripts/build_map_assets.py
```

Interactive terrain is generated by the cartographic pipeline under
`../outputs/interactive-terrain/`. The website does not recompute its geometry,
textures, or camera. It copies the canonical package after verifying file
sizes and SHA-256 checksums:

```bash
../.venv/bin/python scripts/sync_interactive_terrain.py
```

Each terrain model shares a single geometry between the Topography and
Orthophoto textures. The initial orthographic camera uses the azimuth and
visual slope of the printable perspective, looking from offshore toward the
reef; horizontal rotation remains unrestricted through 360°.

Derived Web files are versioned under `public/maps/` and `public/terrain/`.
Source GeoTIFFs remain local and are never published. The shared
`public/west-coast-locator.webp` basemap is referenced only once; clickable
positions are calculated from each site's UTM marker.

## Publishing

The Sites configuration is stored in `.openai/hosting.json`. The vinext build
produces an application compatible with Cloudflare Workers:

```bash
npm run build
```

The canonical deployment uses
<https://reunion.divetopo.com>. The Sites address
<https://plans-sites-plongee-reunion.m-foll.chatgpt.site> remains available as
a technical address. The former project
<https://reliefs-ouest-reunion.m-foll.chatgpt.site> remains online separately;
its configuration is preserved in commit `b9bca34`.
